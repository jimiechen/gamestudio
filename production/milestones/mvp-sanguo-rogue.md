# MVP 里程碑规划：三国像素幸存者

> **目标**：1-2 个月内完成可玩的 MVP 版本  
> **团队规模**：1-2 人（独立开发者）  
> **引擎**：Godot 4.6

---

## 里程碑概览

```
Week 1-2: 核心框架
Week 3-4: 武将系统
Week 5-6: 内容填充
Week 7-8: 打磨发布
```

---

## Week 1-2: 核心框架

### 目标
建立游戏的基础框架，实现核心幸存者循环

### 任务清单

#### Week 1: 基础系统
- [ ] **Day 1-2**: 项目设置和基础架构
  - Godot 4.6 项目创建
  - 项目结构规划
  - 基础输入系统（虚拟摇杆）
  
- [ ] **Day 3-4**: 玩家控制系统
  - 角色移动（虚拟摇杆）
  - 碰撞检测
  - 摄像机跟随
  
- [ ] **Day 5-7**: 自动攻击系统
  - 攻击范围检测
  - 投射物系统
  - 伤害计算

#### Week 2: 游戏循环
- [ ] **Day 8-10**: 敌人系统
  - 基础敌人 AI（追踪玩家）
  - 敌人生成系统
  - 敌人波次系统
  
- [ ] **Day 11-12**: 升级系统
  - 经验值系统
  - 升级界面（三选一）
  - 技能效果应用
  
- [ ] **Day 13-14**: UI 基础
  - 血条/经验条
  - 游戏开始/结束界面
  - 暂停菜单

### Week 2 完成标准
- [ ] 玩家可以移动和自动攻击
- [ ] 敌人会追踪玩家
- [ ] 击败敌人获得经验并升级
- [ ] 基础UI可用
- [ ] 游戏可以开始和结束

## Week 3-4: 武将系统

### 目标
实现武将选择、招募和技能系统

### 任务清单

#### Week 3: 武将框架
- [ ] **Day 15-17**: 武将数据结构
  - 武将资源定义（Resource）
  - 武将属性系统（攻击、防御、速度）
  - 武将技能定义

- [ ] **Day 20-21**: 武将表现
  - 武将像素画（5个MVP武将）

#### Week 4: 军团系统

  - 2人军团实现
  - 武将切换/控制
  
- [ ] **Day 25-26**: 技能系统
  - 5个MVP武将的技能实现
  - 技能升级效果
  - 技能视觉表现
  
- [ ] **Day 27-28**: 武将平衡
  - 基础数值调整
  - 技能效果测试
  - 简单平衡迭代

### Week 4 完成标准
- [ ] 5个武将可用（关羽、赵云、吕布、诸葛亮、貂蝉）

## 风险和对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| 同屏敌人性能问题 | 高 | 高 | Week 1就开始性能测试，使用对象池 |
| 武将平衡难以把握 | 中 | 中 | Week 4专门留时间平衡，MVP武将数量控制在5个 |
| 美术资源不足 | 中 | 高 | 使用像素画降低工作量，考虑购买素材包 |
| 移动端操作不适 | 中 | 高 | Week 1就确定虚拟摇杆方案，早期测试 |
| 开发时间超支 | 高 | 中 | 严格MVP范围，非核心功能后置 |

## 成功标准

### MVP 完成标准
- [ ] 5个可玩武将，每个有独特技能
- [ ] 1个完整关卡（长坂坡）
- [ ] 15-20分钟游戏时长
- [ ] 流畅的60FPS体验
- [ ] 无明显Bug

### 发布后指标
- [ ] 次日留存率 > 30%
- [ ] 平均游戏时长 > 10分钟
- [ ] 用户评分 > 4.0

## 资源需求

### 美术资源
- 角色像素画：5个武将 + 3种敌人 + 1个Boss = ~20张
- 场景像素画：1个关卡背景 + 障碍物 = ~10张
- UI元素：按钮、血条、图标等 = ~30个

### 音效资源
- 音效：攻击、受伤、升级、UI等 = ~15个
- 音乐：1-2首背景音乐

### 开发工具
- Godot 4.6
- Aseprite（像素画）
- Bfxr（音效生成）
- Git（版本控制）
