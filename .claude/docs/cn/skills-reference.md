# 可用技能（斜杠命令）

| 命令 | 用途 |
|---------|-------------|
| `/start` | 首次入门 — 询问你当前的位置，然后引导你到正确的工作流程 |
| `/design-review` | 审查游戏设计文档的完整性和一致性 |
| `/code-review` | 对文件或变更集进行架构代码审查 |
| `/playtest-report` | 生成结构化的游戏测试报告模板 |
| `/balance-check` | 分析游戏平衡数据并标记异常值 |
| `/sprint-plan` | 生成或更新冲刺计划 |
| `/bug-report` | 创建结构化的 Bug 报告 |
| `/architecture-decision` | 创建架构决策记录（ADR） |
| `/asset-audit` | 审计资源的命名、尺寸和流程合规性 |
| `/milestone-review` | 审查里程碑进度并生成状态报告 |
| `/onboard` | 为新贡献者或智能体生成入门上下文 |
| `/prototype` | 搭建一次性原型以测试机制或技术方法 |
| `/release-checklist` | 为当前构建生成并验证发布前检查清单 |
| `/changelog` | 从 git 提交和冲刺数据自动生成变更日志 |
| `/retrospective` | 运行结构化的冲刺或里程碑回顾 |
| `/estimate` | 生成包含复杂度和风险分解的结构化工作量估算 |
| `/hotfix` | 带审计追踪的紧急修复工作流，绕过正常冲刺流程 |
| `/tech-debt` | 扫描、跟踪、优先处理和报告整个代码库的技术债务 |
| `/scope-check` | 根据原始计划分析功能或冲刺范围，标记范围蔓延 |
| `/localize` | 本地化工作流：扫描硬编码字符串、提取、验证翻译 |
| `/perf-profile` | 带瓶颈识别和建议的结构化性能分析 |
| `/project-stage-detect` | 自动分析项目状态、检测阶段、识别差距并推荐下一步 |
| `/reverse-document` | 从现有实现生成设计或架构文档（从代码反向工作） |
| `/team-combat` | 协调战斗团队：game-designer + gameplay-programmer + ai-programmer + technical-artist + sound-designer + qa-tester |
| `/team-narrative` | 协调叙事团队：narrative-director + writer + world-builder + level-designer |
| `/team-ui` | 协调 UI 团队：ux-designer + ui-programmer + art-director |
| `/team-release` | 协调发布团队：release-manager + qa-lead + devops-engineer + producer |
| `/team-polish` | 协调打磨团队：performance-analyst + technical-artist + sound-designer + qa-tester |
| `/team-audio` | 协调音频团队：audio-director + sound-designer + technical-artist + gameplay-programmer |
| `/team-level` | 协调关卡团队：level-designer + narrative-director + world-builder + art-director + systems-designer + qa-tester |
| `/launch-checklist` | 跨所有部门完成发布准备验证 |
| `/patch-notes` | 从 git 历史和内部数据生成面向玩家的补丁说明 |
| `/brainstorm` | 使用专业工作室方法进行引导式构思（MDA、SDT、Bartle、动词优先） |
| `/gate-check` | 验证开发阶段之间的准备情况（通过/关注/失败） |
| `/map-systems` | 将游戏概念分解为系统，映射依赖关系，优先设计顺序，指导每个系统的 GDD |
| `/design-system` | 为单个游戏系统提供引导式、分段的 GDD 编写，包含交叉引用和增量写入 |
| `/setup-engine` | 配置引擎 + 版本，检测知识差距，填充版本感知参考文档 |
